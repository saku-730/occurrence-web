入力として、論文PDFから抽出したテキストと、論文のページ画像が与えられます。
これらは同一の論文に由来する情報です。

テキストと画像を相互に参照し、本文、表、図、地図、キャプション、標本リスト、採集地点一覧などから、生物の分類情報と、その生物が実際に記録・採集・観察された地点・採集年月日を抽出してください。

最重要原則は次の3つです。
1. 「1 Occurrence = 1分類群 × 1地点」とし、1つのOccurrenceに複数地点をまとめないこと。
2. scientificName の属名は必ず完全形にすること。属名略記が1件でも残ったJSONは不正な出力です。
3. すべてのOccurrenceに eventDate キーを必ず含めること。日付を特定できなければ JSON の null を使用してください。

## 抽出ルール

1. scientificName / 生物の分類情報
- 論文から読み取れる最も下位の特定可能な分類群を使用してください。種まで分かれば種、分からなければ属・科などを使用してください。
- Occurrenceそのもの、種小名、地点、採集年月日を存在しないものとして創作してはいけません。
- scientificName は論文中で意図されている分類群を表し、accepted nameや別のsynonymへの置換を目的としません。

### 属名略記は絶対禁止
- scientificName の先頭の属名トークンを `P.`、`M.`、`A.`、`Ph.` などの略記のまま出力してはいけません。
- `P. agrestis`、`M. hilgendorfi`、`A. corticis`、`Ph. agrestis` のような値はすべて不正です。最終JSONには1件も含めないでください。
- 省略形を見つけたら、必ず最も可能性が高い完全な属名へ展開してください。100%の確証は不要です。
- 候補が複数でも1つを選んでください。略記を残すことや、そのOccurrenceを捨てることは禁止です。
- 判断には、近傍の完全学名、同じ節・表・図・分類群一覧、論文タイトル・abstract・keywords、論文全体で扱う分類群を使ってください。それでも不明なら一般的な生物学・分類学の知識から最も妥当な属を推定してください。
- 例: ミミズの文脈で `P. agrestis` が `Pheretima agrestis` を指すのが最も妥当なら、論文中に完全な `Pheretima` 表記がなくても `Pheretima agrestis` と出力してください。
- JSONを出力する直前に全 scientificName の先頭トークンを確認し、属名略記が1件でもあれば完全形へ書き換えてから出力してください。

2. locality / 位置情報
- その分類群が実際に記録、採集、観察された個々の地点を locality に記録してください。
- locality には、1レコードにつき1地点だけを入れてください。
- 複数地点を列挙した文章、括弧内リスト、表の複数地点、`・`、`,`、`、`、`;`、`/`、箇条書き、`および`、`and` などで明示的に分かれた複数の地点は、それぞれ別のOccurrenceに分割してください。
- `4か所`、`3地点`、`複数地点`などの集約表現と個別地点名が併記されている場合、集約表現をlocalityに残さず、個別地点ごとに分割してください。
- locality に複数地点を括弧や区切り文字でまとめた文字列を作ってはいけません。
- 個別地点名が明示されている場合は、その地点名を維持しつつ、必要な上位行政区画だけを補完してください。
- 広域の地域名だけが1つの記録地点として示され、個別の複数地点名が存在しない場合は、その地域名を1つのlocalityとして扱って構いません。

### 日本の都道府県補完
- 日本の locality が市・区・郡・町・村などから始まり都道府県名が省略されている場合、論文の地域文脈から最も可能性が高い都道府県を推定して先頭に補ってください。100%の確証は不要です。
- 推定には、論文タイトル、調査地域の説明、周辺本文、表・図の見出し、同じ論文中の他の地名を使ってください。
- 例: 論文文脈から奈良県内と判断できる `香芝市真美ヶ丘` は `奈良県香芝市真美ヶ丘` としてください。
- 地点そのものを別の場所へ変更してはいけません。補うのは既存地点の上位行政区画だけです。
- すでに都道府県名が含まれている場合は重複して追加しないでください。

### 複数地点の分割例
論文に次のようにある場合:
`P. agrestis は奈良市2か所（大慈仙町・奈良公園）で記録された。`

禁止される出力:
{
  "scientificName": "P. agrestis",
  "locality": "奈良市2か所(大慈仙町・奈良公園)",
  "eventDate": null
}

正しい出力は2件です:
{
  "scientificName": "Pheretima agrestis",
  "locality": "奈良県奈良市大慈仙町",
  "eventDate": null
}
{
  "scientificName": "Pheretima agrestis",
  "locality": "奈良県奈良市奈良公園",
  "eventDate": null
}

3. eventDate / 採集・観察年月日
- 各Occurrenceに対応する実際の採集日・観察日・記録日を eventDate に入れてください。論文の出版年は使わないでください。
- eventDate は必ず `YYYY`、`YYYY-MM`、`YYYY-MM-DD`、または同形式の `開始/終了` のいずれかに正規化してください。
- 例: `1998年` → `1998`、`1998年6月` → `1998-06`、`1998年6月4日` → `1998-06-04`、`1998年5月から7月` → `1998-05/1998-07`。
- 月や日が不明なときに `01` などを補ってはいけません。分かる精度まで落としてください。
- 和暦は西暦へ変換できる場合に変換してください。
- `5月上旬` のような曖昧な表現は、年と月まで確実なら `YYYY-MM` としてください。
- 対応する日付が不明、曖昧すぎる、または上記形式へ安全に変換できない場合は、必ず null としてください。元の日本語・英語の日付文字列をそのまま eventDate に入れてはいけません。
- eventDate の取得に失敗してもOccurrence自体を捨ててはいけません。eventDateだけを null にしてください。

4. 分類群・位置・日付の対応
- 分類群と、その分類群が記録された位置情報・採集年月日を論文内の対応関係のまま組み合わせてください。
- 本文に分類群があり、対応する地点や日付が表や図にある場合など、テキストと画像を組み合わせて対応関係を判断してください。
- 同じ分類群が複数地点に存在する場合は地点数と同じだけ別レコードにしてください。
- 同じ地点に複数分類群が存在する場合は分類群ごとに別レコードにしてください。
- 属名展開と都道府県補完には推定を使って構いませんが、Occurrenceと地点・日付の対応を勝手に作ってはいけません。

5. 情報源の統合
- テキストと画像に同じ情報が存在する場合、重複したOccurrenceとして出力しないでください。
- テキスト・表・図・画像・キャプションを相互に補完して構いませんが、行・列・ラベルの対応関係を崩さないでください。

6. 正確性
- Occurrenceの存在、種小名、地点、採集年月日は論文にある情報を根拠にしてください。
- 存在しないOccurrence、種小名、地点、採集年月日を創作しないでください。
- 属名の省略展開と、日本の既存localityへの都道府県補完だけは推定を許可します。
- 情報が存在しない locality と eventDate には null を使用してください。

7. 出力前の必須チェック
- scientificName の先頭に属名略記が1件も残っていないこと。残っていれば必ず完全形へ直すこと。
- locality が1地点だけであること。
- locality に `4か所(...)` のような複数地点の集約文字列が残っていないこと。
- 日本の行政地名で都道府県が省略されている場合、論文文脈から補完されていること。
- すべてのOccurrenceに eventDate キーがあること。
- eventDate が文字列の場合は `YYYY`、`YYYY-MM`、`YYYY-MM-DD`、またはそれらの `開始/終了` 形式であること。それ以外は null にすること。
- 同じ分類群に複数地点がある場合、それぞれ独立したOccurrenceになっていること。

8. 重複禁止と終了
- scientificName と locality と eventDate の組み合わせが同一のOccurrenceは1件だけ出力してください。
- 略記と完全形が同じ分類群を指す場合、完全形へ統一してから重複判定してください。
- 出力前に全レコードを照合し、同一のOccurrenceを統合してください。
- 同じOccurrenceを繰り返し出力しないでください。
- 抽出した重複のないOccurrenceをすべて1回ずつ出力したら、occurrences配列とJSONオブジェクトを直ちに閉じて生成を終了してください。
- occurrences配列を最初から作り直したり、同じJSONを複数回出力したりしないでください。
- JSONの前後に説明、注釈、Markdownのコードブロックを出力しないでください。

## 出力形式

以下のJSONだけを出力してください。

{
  "occurrences": [
    {
      "scientificName": "省略していない完全な分類群名",
      "locality": "1つだけの地点名",
      "eventDate": "1998-06"
    }
  ]
}

日付を特定できないOccurrenceでは:

{
  "scientificName": "省略していない完全な分類群名",
  "locality": "1つだけの地点名",
  "eventDate": null
}

該当するOccurrenceが存在しない場合:

{
  "occurrences": []
}
