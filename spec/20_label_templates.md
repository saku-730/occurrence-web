# ラベル印刷・ラベルテンプレート仕様と実装状況

## 1. この文書の目的

この文書は、occurrenceのラベル作成、プレビュー、印刷、PDF出力、および利用者独自のラベルテンプレート作成機能について、2026年9月10日時点の実装状況と今後の実装方針を記録する。

現在は、固定されたデフォルトラベルによる印刷機能は利用できる。一方、利用者が作成したテンプレートはブラウザ内へ試験的に保存されるだけで、ラベル生成にはまだ使われない。以下では、実装済み、暫定実装、未実装を明確に分ける。

## 2. 関連する実装

主なフロントエンド実装は以下にある。

- `frontend/src/app/occurrences/search/page.tsx`
  - occurrenceの選択
  - ラベル作成ダイアログの起動
  - ラベルテンプレート作成画面へのリンク
- `frontend/src/components/occurrence-label-preview.tsx`
  - デフォルトラベルの描画
  - A4全体・個別プレビュー
  - QRコード生成
  - 印刷・PDFダウンロード
- `frontend/src/app/label-templates/new/page.tsx`
  - 利用者独自テンプレートの作成画面
  - プレビュー
  - `localStorage`への暫定保存

バックエンドには、ラベルテンプレート用のmigration、repository、service、handler、route、OpenAPI定義はまだない。

## 3. 検索結果からのラベル作成

### 3.1 実装済みの操作

検索結果の各行にチェックボックスがあり、利用者はラベルを作成するoccurrenceを複数選択できる。表示中の検索結果を一括選択・解除するチェックボックスもある。

1件以上を選択すると `ラベル作成` ボタンを使用できる。ボタンを押すと、選択したoccurrenceを渡してラベル作成ダイアログを開く。

現状のラベル作成は、検索結果として閲覧できたデータを対象とする。ラベル作成自体について所有者限定の判定はなく、未ログイン利用者も公開データを選択してラベルを作成できる。

### 3.2 選択状態の現在の制約と重複排除

- 新しい検索を実行すると選択状態は解除される。
- 次ページの取得も検索処理を再実行するため、ページをまたいで選択状態を保持できない。
- ラベルの並び順はチェックした順番ではなく、現在の検索レスポンス内の並び順である。
- 検索一覧の表示とラベルへ渡すデータは、どちらも `uniqueOccurrenceItems()` を通してoccurrence ID単位で重複排除する。
- そのため、バックエンド検索結果に同じoccurrenceが複数行含まれていても、画面上では1行として扱われ、選択した1 occurrenceにつき生成されるラベルも1枚となる。
- 選択件数も一意なoccurrence ID数で管理するため、表示された選択件数と生成されるラベル枚数が一致する。

重複した検索行によってラベルが複数生成される問題は、2026年9月10日に修正済みである。

## 4. デフォルトラベル

デフォルトラベルはコードに固定された変更不可のテンプレートである。PostgreSQLや`localStorage`には保存しない。

### 4.1 印刷寸法と配置

- ラベル寸法: 横40mm x 縦20mm
- QRコード表示寸法: 15mm x 15mm
- ラベル背景: 白
- 文字色: 黒
- ラベル内余白: 1mm
- ラベル枠: 1pxの実線
- 文字サイズ: 2.5mm
- QRコードと文字領域の間隔: 1mm
- QRコードの周囲: 0.25mmの白い余白

QRコード用に横15mmの専用列を確保し、文字がQRコードの背後へ回り込まないようにしている。

各ラベルが個別に枠線を持ち、ラベル間隔は0である。このため、隣接辺は画面・PDF上で二重の太さに見える可能性がある。

### 4.2 表示内容

ラベルには次の値を表示する。

- 学名
- 作成者のユーザー名
- 緯度・経度
- 作成日
- occurrence詳細URLのQRコード

項目名、occurrence ID、および `OCCURRENCE` の見出しは表示しない。

表示値がない場合の現在の挙動は以下である。

- 学名: 行自体を表示しない。「学名未登録」とは表示しない。
- 作成者: `-` を表示する。
- 緯度・経度: 両方が取得できた場合だけ表示する。片方だけの場合は両方とも表示しない。
- 作成日: `-` を表示する。
- QRコード: 生成に失敗した場合は表示しない。

作成日はブラウザの日本語ロケールで日付だけに整形し、時刻は表示しない。

### 4.3 データの取得元

検索レスポンスから、occurrence ID、occurrence URI、作成者ユーザーID、学名、作成日時を受け取る。

作成者名は検索画面が `/users/{user_id}` を呼び出して取得する。取得できない場合は `-` となる。

緯度・経度はラベル作成ダイアログを開いた後、選択したoccurrenceごとに `GET /occurrences/{id}` を呼び出し、返却されたN-Quadsから以下のリテラルを抽出する。

- `http://rs.tdwg.org/dwc/terms/decimalLatitude`
- `http://rs.tdwg.org/dwc/terms/decimalLongitude`

詳細APIの失敗またはN-Quadsの解析失敗は画面上のエラーにせず、緯度・経度なしとして扱う。選択件数と同数の詳細API呼び出しが発生するため、件数が多い場合はN+1リクエストになる。

### 4.4 QRコード

QRコードには検索レスポンスの `occurrence_uri` を格納する。クライアント側で`qrcode`を使ってData URLを生成する。

現在の生成設定は以下である。

- 誤り訂正レベル: M
- 内部margin: 0
- 生成画像: 256px
- 前景色: `#182126`
- 背景色: 白

印刷上の余白はQR画像自体ではなく、表示要素の白いpaddingで確保する。

## 5. プレビュー

ラベル作成ダイアログには `A4全体` と `個別` の2つの表示モードがある。初期表示は `A4全体` である。

ダイアログは、閉じるボタン、右上の閉じるアイコン、または背景部分のクリックで閉じる。Escapeキーによる閉じる処理は未実装である。

### 5.1 A4全体

- 用紙: A4縦、210mm x 297mm
- 用紙余白: 上下10mm、左右5mm
- 配置: 5列 x 13行
- 1ページ当たり: 最大65ラベル
- ラベル間隔: 0
- 65件を超えた場合: 65件単位でA4ページを追加

5列 x 40mmと左右余白5mmずつでA4横幅210mmを使用する。13行 x 20mmと上下余白10mmずつでは用紙下部に17mmの未使用領域が残る。

現在の5列 x 13行は、デフォルトの40mm x 20mmラベル専用の固定値である。利用者テンプレートの寸法を反映する際は、A4の印刷可能領域から列数、行数、ページ当たり枚数を計算し直す必要がある。

### 5.2 個別

選択したラベルを1件ずつ表示し、前後ボタンで切り替える。現在位置と総件数も表示する。

個別表示は40rem x 20remの拡大表示で、縦横比はデフォルトラベルと同じ2:1である。個別表示用の文字とQRコードも拡大されるが、内容と配置比率は印刷ラベルを反映する。

## 6. 印刷とPDF

印刷ボタンとPDFダウンロードボタンは、`A4全体` モードだけに表示する。

### 6.1 PDF生成

ブラウザで`html2canvas`と`jspdf`を動的に読み込み、A4プレビューのDOMをページごとに画像化する。画像化時のscaleは2、背景色は白である。その画像をA4縦のPDFへ配置する。

- ファイル名: `occurrence-labels.pdf`
- 65件を超える場合: 複数PDFページ
- PDFの内容: ベクター文字ではなく、A4プレビューをラスタ画像化したもの

そのため、PDF内の文字検索・コピーは保証されず、出力品質と物理寸法はブラウザ描画、`html2canvas`、PDF表示ソフト、プリンター設定の影響を受ける。

### 6.2 印刷

印刷時も同じPDFを生成し、Blob URLを別ウィンドウで開いて印刷ダイアログを呼び出す。PDF読み込み時に印刷を開始し、読み込みイベントが発生しない場合に備えて1.5秒後にも印刷を試みる。

PDF生成中は操作ボタンを無効化する。生成に失敗した場合は `PDFを作成できませんでした` と表示する。

## 7. ラベルテンプレート作成画面

検索画面の `ラベルテンプレート` は、`/label-templates/new` へのテキストリンクである。

### 7.1 現在の入力項目

- テンプレート名
- 横幅mm
- 縦幅mm
- QRコードmm
- 表示項目

初期値は以下である。

- テンプレート名: 空
- 横幅: 40mm
- 縦幅: 20mm
- QRコード: 15mm
- 表示項目: すべて選択済み

選択可能な表示項目は以下の5種類だけである。

| 保存値 | 画面上の名称 |
|---|---|
| `scientificName` | 学名 |
| `creator` | 作成者 |
| `coordinates` | 緯度経度 |
| `created` | 作成日 |
| `qrCode` | QRコード |

### 7.2 作成画面のプレビュー

入力した横幅と縦幅の比率でサンプルラベルを表示する。プレビューは最大横幅20remの画面表示であり、mm単位の物理サイズではない。

サンプル値は以下で固定されている。

- 学名: `Quercus serrata`
- 作成者: `Yamada Taro`
- 緯度・経度: `36.225333, 140.106861`
- 作成日: `2026年7月28日`
- QRコード: 実際のQRコードではなく `QR` と書いた枠

QRコードのプレビュー寸法は、入力したmm値を係数2.6でpxへ換算した近似表示である。ラベル内に収まることは現在検証されない。

### 7.3 暫定保存形式

現在はバックエンドを呼び出さず、ブラウザの`localStorage`へJSON配列として保存する。

- キー: `occurrence-web.label-templates`
- ID: ブラウザの`crypto.randomUUID()`で生成
- 保存単位: 既存配列へ新規テンプレートを追加し、配列全体を書き戻す

現在保存する構造は以下である。

```json
{
  "id": "uuid",
  "name": "テンプレート名",
  "width_mm": 40,
  "height_mm": 20,
  "qr_size_mm": 15,
  "fields": [
    "scientificName",
    "creator",
    "coordinates",
    "created",
    "qrCode"
  ]
}
```

### 7.4 現在の入力検証

送信時に以下だけを検証する。

- テンプレート名をtrimした結果が空でないこと
- 横幅、縦幅、QRコード寸法がそれぞれ0より大きいこと

数値入力にはHTML上で`min=1`、`step=1`を指定する。

次の検証は未実装である。

- 有限値であること
- 上限寸法
- QRコードがラベル内に収まること
- 表示項目を1つ以上選択していること
- 許可された表示項目だけであること
- テンプレート名の長さ
- 同じ利用者内での名前重複
- 破損・改変された`localStorage`データの構造検証

`localStorage`に不正なJSONがある場合は保存に失敗し、汎用エラーを表示する。自動修復や旧形式からのmigrationはない。

### 7.5 暫定実装の制約

- 同一ブラウザ・同一オリジンでしか参照できない。
- ログインユーザーとの所有関係がない。
- 未ログインでも作成できる。
- 他端末同期、認可、バックアップがない。
- 作成済みテンプレートの一覧、詳細、編集、削除画面がない。
- 作成成功後もフォーム初期化や画面遷移はしない。
- 保存したテンプレートを読み込んでラベル作成へ適用する処理がない。
- デフォルトラベルとテンプレート作成画面で型・描画処理を共有していない。
- 保存形式のversion情報がなく、将来の形式変更に対応するmigration方針がない。

## 8. PostgreSQL永続化の方針

ラベルテンプレートは、生物学的意味関係を表すRDFではなく、利用者単位の画面・印刷設定である。このためFusekiではなくPostgreSQLに保存する。

Goose migrationで、少なくとも以下の`label_templates`テーブルを追加する。

```text
id UUID PRIMARY KEY
user_id UUID NOT NULL REFERENCES users(id)
name TEXT NOT NULL
width_mm INTEGER NOT NULL
height_mm INTEGER NOT NULL
qr_size_mm INTEGER NOT NULL
fields JSONB NOT NULL
created_at TIMESTAMPTZ NOT NULL
updated_at TIMESTAMPTZ NOT NULL
```

実装時には、利用者ごとの名前重複を許可するかを決定し、許可しない場合は`UNIQUE (user_id, name)`を追加する。利用者削除時の外部キー動作も既存のユーザー削除方針に合わせて決定する。

デフォルトラベルはコード上の固定テンプレートとして残し、テーブルには保存しない。

## 9. 予定するAPIと認可

ログイン済み利用者だけが、自分のテンプレートを操作できるようにする。

- `POST /label-templates`: テンプレート作成
- `GET /label-templates`: 自分のテンプレート一覧取得
- `GET /label-templates/{id}`: 自分のテンプレート取得
- `PUT /label-templates/{id}`: 自分のテンプレート更新
- `DELETE /label-templates/{id}`: 自分のテンプレート削除

認可とHTTPステータスは以下とする。

- 未ログイン: `401 Unauthorized`
- 自分のテンプレート: 操作可能
- 存在しないテンプレート: `404 Not Found`
- 他人のテンプレート: 存在を通知しないため`404 Not Found`

バックエンドでは以下を検証する。

- 寸法が有限の正数であり、定めた上限以内であること
- QRコードがラベル内に収まること
- `fields`が許可済みの値だけで構成されること
- 表示項目が1つ以上あること
- テンプレート名が空でなく、定めた最大長以内であること

API追加時はOpenAPIと`spec/11_api_contract.md`を更新する。

## 10. テンプレート適用時に必要な設計

保存したテンプレートをラベル作成で使うには、少なくとも以下が必要である。

- ラベル作成ダイアログで、デフォルトまたは自分のテンプレートを選択するUI
- A4、個別、PDF、印刷が同じテンプレート定義を使用する共通描画コンポーネント
- テンプレート寸法からA4の列数・行数・ページ数を計算する処理
- ラベル外にはみ出すQRコードや文字の扱い
- 長い学名、作成者名、座標の折り返し、省略、最大行数
- 表示項目の順序を固定するか、利用者が変更できるか
- 作成済みテンプレートの一覧、編集、削除画面
- `localStorage`暫定実装の削除

現在の`fields`は表示・非表示だけを表す。項目順、座標、文字サイズ、余白、罫線、用紙方向などは保存できない。これらを編集可能にする場合も、任意HTMLや任意CSSは保存・実行せず、許可されたレイアウト属性だけを構造化データとして扱う。

## 11. 実装順序

1. **完了**: ラベル対象を重複排除済み検索結果から作り、表示件数とラベル枚数を一致させる。
2. PostgreSQL migrationとrepositoryを追加する。
3. serviceで作成・取得・更新・削除とvalidationを実装する。
4. handler、route、認可、OpenAPIを追加する。
5. `/label-templates/new`をAPI保存へ変更する。
6. 一覧・編集・削除画面を追加する。
7. ラベル作成ダイアログへテンプレート選択を追加する。
8. デフォルトと利用者テンプレートで描画処理を共通化する。
9. 寸法に応じたA4配置を実装する。
10. `localStorage`の暫定保存コードを削除する。

## 12. テスト要件

バックエンドテストを追加する場合は、必ずテストコードより先に`backend/test.md`へテスト内容を追記する。

### 12.1 バックエンド

- service: 正常なテンプレートの作成、一覧、単体取得、更新、削除
- service: 名前、寸法、QR寸法、表示項目のvalidation
- service: 他ユーザーのテンプレートを取得・更新・削除できないこと
- handler: 未ログインが`401`になること
- handler: 他ユーザーまたは存在しないIDが`404`になること
- PostgreSQL統合: 実DBへ保存し、同じ内容を取得できること
- PostgreSQL統合: 更新日時と所有者条件が正しく適用されること

### 12.2 フロントエンド

- 検索結果の一括選択・個別選択と選択件数
- 重複した検索行からラベルが重複生成されないこと
- A4で65件ごとにページが分かれること
- 個別表示の前後移動と境界でのボタン無効化
- 学名欠落、作成者欠落、座標片側欠落、日付欠落時の表示
- QRコードがoccurrence URIを格納すること
- 作成済みテンプレートを選ぶとA4、個別、PDFへ同じ項目と寸法が反映されること
- テンプレート寸法に応じてA4配置数が変わること
- PDFが選択件数分のラベルを含むこと
- ページ移動時の選択保持を実装する場合、その回帰テスト

### 12.3 現在のテスト状況

2026年9月10日時点で、フロントエンドの`npm run typecheck`は成功する。

一方、ラベル作成・PDF出力・`localStorage`テンプレート保存について、専用の自動テストは現時点で確認できない。したがって、ラベル枚数、A4ページ分割、PDF内容、物理印刷寸法、文字切れ、QRコードの読み取りは自動的に回帰検証されていない。

## 13. 現在の完成条件

現時点では、固定デフォルトラベルを使った検索結果からのラベル作成、A4・個別プレビュー、PDFダウンロード、印刷までが試用可能である。

ラベルテンプレート機能は、作成画面とブラウザ内への暫定保存までの試作段階である。PostgreSQLへの永続化、ユーザー所有権、CRUD API、一覧・編集・削除、ラベルへの適用が完了するまでは、機能完成とは扱わない。
