# Storage<no value>

Bio Databaseでは、データの性質に応じてPostgreSQL、Fuseki、Garageを使い分けます。この役割分担はアプリケーション設計の中心です。

## PostgreSQLに保存するもの

PostgreSQLには、整合性のある更新と認証処理が必要なデータを保存します。

- ユーザー
- 認証情報
- セッション
- パスワードリセットトークン
- メディアのメタデータ

## Fusekiに保存するもの

Fusekiには、生物学的な意味関係を持つRDFデータを保存します。

- オカレンス
- Identification、Event、Location
- Darwin Coreなどの語彙
- GBIF Backbone Taxonomy
- オカレンスとメディアURIの関連

## Garageに保存するもの

Garageには、画像や添付ファイルなどの大容量バイナリを保存します。

- 画像
- 音声
- 動画
- そのほか対応する添付ファイル

## なぜ一つのDBに統合しなかったか

ユーザー、認証、権限などは整合性を重視するリレーショナルデータです。生物学的なオカレンスは、語彙とリソース間の意味関係をたどるRDFデータです。画像や動画は、大容量バイナリを効率よく保存・配信するオブジェクトです。

これらを一つのデータベースへ統合すると、それぞれに必要な検索、更新、容量管理、アクセス制御を不自然に実装することになります。役割ごとにストアを分けることで、各データの性質に合った管理を行います。
